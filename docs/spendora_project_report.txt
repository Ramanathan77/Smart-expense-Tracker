CHAPTER 1: INTRODUCTION & LITERATURE REVIEW

1.1 Introduction
In an increasingly complex economic environment, effective personal financial management is crucial for maintaining financial stability and achieving long-term goals. Spendora is a comprehensive, fullstack smart expense tracking application designed to simplify the process of monitoring income, tracking expenses, and analyzing financial behaviors. Unlike traditional manual ledgers or basic spreadsheet-based tracking methods, Spendora leverages modern web technologies and Artificial Intelligence (AI) to provide a seamless, intuitive, and highly interactive user experience. The system is built using a robust Java Spring Boot backend, a dynamic React frontend, and a MySQL relational database, incorporating the Google Gemini AI API to deliver personalized financial insights.

1.2 Motivation
The primary motivation behind developing Spendora stems from the growing need for accessible and intelligent financial management tools. Many individuals struggle to maintain consistent records of their daily transactions, leading to a lack of awareness regarding their spending habits. Furthermore, existing solutions often suffer from cluttered user interfaces, lack of real-time insights, or exorbitant subscription fees. Spendora aims to democratize financial intelligence by offering a visually stunning, neon-glassmorphism themed application that not only tracks data but interprets it using state-of-the-art AI.

1.3 Problem Statement
Traditional expense tracking mechanisms are predominantly static, requiring manual data entry and offering limited analytical capabilities. Users often find it tedious to categorize expenses, calculate total outgoings, and identify areas where they can save money. Furthermore, standard financial applications lack predictive or conversational intelligence, leaving users to interpret raw charts and graphs on their own. The problem is thus twofold: first, there is a lack of visually engaging and user-friendly interfaces in financial apps; second, there is an absence of automated, personalized financial advice derived directly from user transaction data.

1.4 Objectives
The core objectives of the Spendora project are as follows:
- To develop a responsive, highly aesthetic user interface utilizing React and a neon-glassmorphism design language.
- To architect a secure and scalable backend infrastructure using Java Spring Boot and MySQL.
- To implement robust authentication and authorization mechanisms using JSON Web Tokens (JWT) and Spring Security.
- To integrate Google Gemini AI to analyze user transaction history and provide dynamic, actionable financial advice.
- To support advanced data management features, including bulk CSV transaction uploads and dynamic currency conversion.

1.5 Literature Review
The intersection of technology and personal finance has evolved significantly over the past decade. 
- Traditional Financial Software: Early iterations of personal finance software, such as Quicken or Microsoft Money, revolutionized digital accounting but were often desktop-bound and lacked cloud synchronization. 
- Mobile and Cloud-Based Trackers: Applications like Mint and YNAB (You Need A Budget) introduced cloud connectivity and automated bank syncing. However, these platforms often feature rigid budgeting frameworks that may not suit all users.
- AI in Financial Services: Recent academic literature and industry trends highlight the growing role of Machine Learning and AI in finance. Studies by various researchers have demonstrated that AI-driven recommendation models can encourage better financial habits by analyzing spending patterns and predicting future cash flows.
- Modern Web Architecture: The shift towards decoupled frontend and backend architectures (e.g., React communicating with a RESTful Spring Boot API) has been thoroughly documented in software engineering literature as a best practice for building scalable, maintainable enterprise applications.

1.6 Existing System vs. Proposed System
Existing systems generally rely on manual entry and offer static, rule-based alerts (e.g., "You have exceeded your food budget"). They rarely provide contextual, human-like advice based on a holistic view of the user's financial behavior. 
The Proposed System (Spendora) differentiates itself by:
1. Utilizing a decoupled Fullstack architecture (React + Spring Boot).
2. Incorporating a dynamic AI Chatbot/Insight Engine powered by Google Gemini, capable of providing conversational, context-aware financial reviews.
3. Employing a unique, engaging glassmorphism UI to increase user retention and satisfaction.
4. Ensuring high security through stateless JWT authentication.

1.7 Scope of the Project
The scope encompasses the end-to-end development of the web application, including database schema design, RESTful API development, frontend UI/UX implementation, AI integration, and final deployment considerations. It is designed primarily for individual users managing personal finances.

CHAPTER 2: FIRST PHASE WORK (REVIEW 01)

2.1 Initial Requirements Gathering
The first phase of the Spendora project involved defining the core functional and non-functional requirements. Functional requirements included user registration, login, adding/editing/deleting transactions, and viewing a dashboard summary. Non-functional requirements emphasized performance, mobile responsiveness, and an ultra-modern aesthetic.

2.2 System Architecture (Initial Concept)
Initially, the project was conceptualized using the MERN stack (MongoDB, Express.js, React, Node.js). The architecture followed a standard monolithic repository approach where the Node.js backend served API endpoints to the React frontend, and data was stored in NoSQL collections. 

2.3 Frontend Design (Neon-Glassmorphism UI)
A major focus of Phase 1 was the UI/UX design. The "glassmorphism" trend was selected for its premium, modern appeal. This involved:
- Utilizing CSS properties like backdrop-filter: blur() to create frosted glass effects.
- Implementing vibrant neon accents (gradients and box-shadows) against a dark mode background.
- Developing modular React components:
  - `Card.jsx`: A reusable glass container.
  - `Button.jsx`: Standardized interactive elements.
  - `Auth.jsx`: A sleek, animated login and registration interface.
  - `Dashboard.jsx`: The primary landing view showing total balance, income, and expenses using dynamic state.

2.4 Database Design (Initial Schema)
In the initial phase, a schema-less NoSQL approach was adopted using MongoDB. The database consisted of two primary collections:
- Users: Storing user credentials (hashed passwords) and email addresses.
- Transactions: Storing individual expense and income records, linked to the user via a reference ID.

2.5 Core Features Implemented
During Review 01, the basic Minimum Viable Product (MVP) was achieved:
- Users could successfully register and log in.
- The Dashboard accurately reflected the sum of all transactions.
- The `Transactions.jsx` page displayed a list of historical data.
- Basic frontend routing was established using React Router.

2.6 Challenges Faced in Phase 1
Several challenges emerged during the first phase:
- State Management: Prop-drilling became an issue as currency preferences and authentication states needed to be accessed across multiple deeply nested components.
- Data Integrity: The lack of strict relational constraints in MongoDB occasionally led to orphaned transactions when testing user deletions.
- API Consistency: Maintaining a stable connection between the Node.js backend and React frontend during rapid development required constant refactoring of the `api.js` service layer.

CHAPTER 3: SECOND PHASE WORK (REVIEW 02) (TECH CHANGES OR ENHANCEMENT)

3.1 Technology Migration Strategy
Based on the challenges faced in Phase 1 and the need for enterprise-level robustness, a major architectural pivot was executed in Phase 2. The backend was completely migrated from Node.js/MongoDB to Java Spring Boot/MySQL. This transition was driven by the need for strict ACID compliance, robust security frameworks (Spring Security), and strongly typed object-oriented backend code.

3.2 Backend Architecture Redesign
The new backend was structured using a classic Controller-Service-Repository pattern in Spring Boot (`src/main/java/com/example/demo/`):
- Application Entry Point: `DemoApplication.java` boots the embedded Tomcat server.
- Controllers (`controller/`): `AuthController.java`, `TransactionController.java`, and `InsightController.java` were created to handle mapping HTTP requests to backend logic.
- Entities (`entity/`): Java classes (`User.java`, `Transaction.java`) were annotated with JPA/Hibernate decorators (`@Entity`, `@Table`) to map directly to MySQL tables.
- Repositories (`repository/`): Interfaces extending `JpaRepository` were implemented, providing out-of-the-box database operations without writing raw SQL.

3.3 Relational Database Implementation
The database was transitioned to XAMPP MySQL. The schema was redesigned to enforce referential integrity.
- The `users` table holds primary keys that act as foreign keys in the `transactions` table.
- Data types were strictly defined (e.g., DECIMAL for monetary values, VARCHAR for categories, TIMESTAMP for dates), ensuring high data quality.

3.4 Security Integration
Security was significantly hardened during Phase 2:
- Spring Security: `SecurityConfig.java` was configured to disable CSRF (as it's a stateless REST API) and define route authorization (e.g., `/api/auth/**` is public, all other routes require authentication).
- JWT Authentication: JSON Web Tokens replaced basic session cookies. 
  - `JwtUtil.java`: Handles generating tokens upon successful login and extracting claims (like username) from incoming tokens.
  - `JwtFilter.java`: A custom OncePerRequestFilter that intercepts every API call, validates the JWT in the Authorization header, and sets the Spring Security Context.
  - `CustomUserDetailsService.java`: Bridges Spring Security with the `UserRepository` to load user credentials during the authentication process.

3.5 AI Integration (Google Gemini API)
The most significant enhancement in Phase 2 was the integration of Artificial Intelligence.
- A `GeminiAiService.java` class was created in the backend to communicate securely with the Google Gemini API.
- The AI was configured to receive an aggregated summary of the user's transaction data (total income, top expense categories, recent large purchases) and return a synthesized, natural language financial review.
- The frontend `Insights.jsx` page was upgraded to include an interactive AI Chatbot interface, allowing users to ask specific questions about their finances and receive context-aware advice, bypassing rate limits by optimizing the context window.

3.6 Advanced Features
- CSV Bulk Upload: Implemented logic to parse CSV files on the frontend and send bulk transaction arrays to the backend, streamlining data entry.
- Dynamic Currency Context: A React `CurrencyContext.jsx` was implemented globally. It allows users to switch between currencies (e.g., USD, INR, EUR) and instantly updates all monetary displays across the application without reloading the page.

CHAPTER 4: ANALYSIS

4.1 System Analysis
The Spendora system operates on a client-server model. The React client is responsible for presentation and local state, while the Spring Boot server manages business logic, AI orchestration, and data persistence. Communication occurs exclusively via JSON over HTTP REST APIs.

4.2 Frontend Code Analysis
The React frontend (`spendora-frontend/src/`) demonstrates modern component-based architecture:
- Hooks: Extensive use of `useState` and `useEffect` for lifecycle management and local state.
- Context API: Used for global state management (Currency and Auth status), avoiding prop-drilling.
- Axios Interceptors: The `services/api.js` file configures Axios to automatically attach the JWT token to the headers of outgoing requests, ensuring seamless authenticated communication.
- Error Handling: An `ErrorBoundary.jsx` component wraps the application to catch JavaScript runtime errors, preventing the UI from crashing completely and displaying a graceful fallback screen.

4.3 Backend Code Analysis
The Spring Boot backend showcases enterprise design patterns:
- Dependency Injection: Heavily utilizes Spring's `@Autowired` (or constructor injection) to wire repositories into controllers, promoting loose coupling.
- Data Transfer Objects (DTOs): While entities handle database mapping, DTOs are used in controllers to shape the JSON payloads sent to and received from the React frontend, preventing over-posting and masking sensitive entity fields (like passwords).
- Environment Variables: Sensitive data, such as the MySQL credentials, JWT secret keys, and the Google Gemini API key, are strictly managed via `.env` files and `application.properties`, keeping them out of version control for security.

4.4 Database Schema Analysis
The relational schema in MySQL consists of:
- `users`: `id` (PK, Auto-increment), `email` (Unique, Varchar), `password` (Varchar, Bcrypt hashed), `created_at` (Timestamp).
- `transactions`: `id` (PK), `user_id` (FK to users.id), `amount` (Decimal), `type` (Enum: INCOME/EXPENSE), `category` (Varchar), `description` (Text), `date` (Date).
This normalized structure eliminates data redundancy and allows for complex queries, such as grouping expenses by category for the AI analysis.

4.5 Security Analysis
The security architecture robustly defends against common web vulnerabilities:
- Passwords are never stored in plaintext; they are hashed using the BCrypt algorithm.
- The use of JWTs protects against Cross-Site Request Forgery (CSRF) attacks, as the token is stored in memory or local storage and explicitly sent in the Authorization header, rather than relying on browser cookies.
- CORS (Cross-Origin Resource Sharing) is explicitly configured in Spring Boot to only accept requests from the trusted React frontend domain (e.g., `http://localhost:5173`), preventing unauthorized domains from accessing the API.

4.6 Performance Analysis
- Frontend: The React Vite bundler provides extremely fast Hot Module Replacement (HMR) during development and highly optimized, minified static assets for production.
- Backend: Spring Boot's HikariCP connection pool efficiently manages database connections, preventing thread starvation under heavy load. The system is designed to be stateless, allowing for horizontal scaling if deployed to cloud environments.

CHAPTER 5: RESULTS AND DISCUSSION

5.1 UI/UX Implementation Results
The finalized user interface successfully achieved the desired neon-glassmorphism aesthetic. Testing across various devices confirmed that the CSS grid and flexbox layouts scale correctly, providing a seamless and intuitive mobile-responsive experience. The theme toggle (Dark/Neon mode) functions flawlessly, enhancing user personalization.

5.2 Backend API Testing Results
Comprehensive testing of the REST APIs via Postman confirmed:
- Authentication endpoints correctly validate credentials and issue valid JWTs.
- Transaction endpoints enforce user-isolation (a user cannot fetch or delete transactions belonging to another user ID).
- Database operations execute with minimal latency.

5.3 AI Insights Accuracy and Responsiveness
The integration of the Google Gemini API yielded highly positive results. When provided with an aggregated transaction payload, the AI successfully returns personalized, logical financial advice (e.g., noting high expenditure in "Dining" and suggesting budgeting strategies). Handling rate limits and context window optimization successfully prevented 404/429 API errors, ensuring the chatbot remains stable during active use.

5.4 System Flow and User Journey Verification
The post-login navigation flow was rigorously tested and fixed. Upon successful authentication, users are correctly redirected to the `Dashboard.jsx`, ensuring a logical progression. The global `CurrencyContext` dynamically updates all numerical values instantly, proving the efficiency of React's Context API.

5.5 Discussion on Tech Stack Choices
The migration from Node.js/MongoDB to Spring Boot/MySQL proved to be a critical success factor. While the MERN stack offered rapid initial prototyping, the Java backend provided superior structure, type safety, and a built-in security ecosystem that significantly accelerated the implementation of robust authentication. The decoupled nature of the application means the React frontend and Spring backend can be deployed and scaled independently.

6.1 Conclusion

By moving through structured development phases, the project evolved from a basic prototype into a robust, secure, and highly aesthetic financial management tool. The integration of cutting-edge AI technologies, specifically the Google Gemini API, elevates Spendora beyond standard expense trackers, transforming it into a personalized financial advisor.
